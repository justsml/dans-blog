So steal the database connection string

One logical dependency deserves one address.

environment · constructor · call site

// init  (keys and URLs come from .env)
new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY })

// every call site
model: "claude-fable-5-1",
max_tokens: 2000,
cache_control: { type: "ephemeral" }

one string

LLM_URL=llm://anthropic/fable-5.1?cache=true&max=2000

// init, anywhere, any language
const model = connect(process.env.LLM_URL)

llm:// (10 min) | slide 2 | 2 minutes

Left: the same dependency configured in the environment, the SDK constructor, and every call site. Nobody chose this; it accreted.

Click: one string, consumed by one connect call, in any language.

Click: the anatomy. Scheme says this is a model. Host says who serves it: a provider alias, a hostname, a gateway, or localhost. Path names the model. Query carries the knobs. A local model is a host, not a new scheme, exactly like postgres:// on your laptop.

Benefits come almost for free

URLs already know how to do this.

The two objections you are already forming

“Every provider is different.” And secrets.

You writeopenaianthropicgoogle

cache=5m—cache_control + ttl 5m—
effort=mediumreasoning_efforteffort—
cache=2hvalidate(): "cache_ttl" must be one of [5m, 1h]. Caught before you spend a token.

Common params normalize. Vendor params get a namespace and pass through. Postgres, MySQL and Redis are not identical either; connection strings standardize the envelope, not every capability.

The userinfo slot exists. Logs, shell history and telemetry say use it sparingly: reference the key, don't paste it.

llm:// (10 min) | slide 4 | 2.5 minutes

The table is real output from the llm-strings normalizer. You write max=2000 once; the library emits max_completion_tokens for OpenAI, max_tokens for Anthropic, maxOutputTokens for Google. cache=5m becomes Anthropic cache control with a TTL, or a Bedrock cache point.

Click: validation. cache=2h fails before the request leaves the process. That is the point of a standard envelope: you can check it.

Click: the two bottom lines. Envelope, not capability. And secrets: the syntax allows a key in the userinfo position, the way postgres:// does. Prefer indirection. Do not make this a fight; nobody in the room disagrees.

Why this matters more in an agentic world

A developer picking a model once can tolerate awkward config. An orchestrator choosing among cloud, local and specialist endpoints at runtime needs a machine-readable model target.

postgres://  redis://  s3://  https://llm:// One string. Any model. Any provider.
