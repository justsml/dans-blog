The proposal

Treat a model like a database connection.

llm://anthropic/fable-5.1?cache=true

llm://Scheme. The resource type: a model.
anthropicHost. The provider, by alias or hostname. A proxy, a gateway, or localhost:11434 are hosts too.
/fable-5.1Path. The model, or a deployment of one.
?cache=trueQuery. Runtime configuration: caching, effort, tokens, temperature.

The parts are not new. Putting them in one string is the whole idea.

llm:// (5 min) | slide 2 | 90 seconds

Here is the entire idea. Provider, model, and runtime configuration in one portable URI. Walk left to right: scheme, host, path, query.

The host is the provider. That answers the question people ask first: what about local models? A local model is a host, not a new scheme. One scheme, many hosts, like postgres:// works for RDS and for your laptop.

Today this information lives in three places: the environment, the SDK constructor, and the call site. One logical dependency smeared across three layers.

Why it pays off immediately

Swapping models should be boring.

Zero application changes

export LLM_URL='llm://openai/gpt-5.6-sol?cache=false'
my-agent

export LLM_URL='llm://anthropic/fable-5.1?cache=true'
my-agent

export LLM_URL='llm://openrouter/glm-5.3-flash?thinking=low&cache=true'
my-agent
PortableLaptop, CI, Docker, serverless, another language.
ParseableEvery language already ships a URL parser.
SerializableStore, pass, compare, override, redact.
Normalizablemax=2000 becomes whatever this provider calls it.

We don't need AI-specific YAML for something URLs have handled for thirty years.

llm:// (5 min) | slide 3 | 90 seconds

Demo moment. Same binary, three exports, three providers, one of them a router. The application consumes one input: here is the model connection.

Right column at speed. Portable, parseable, serializable: free because it is a URL. The fourth row is the one that answers "every provider is different." The library normalizes common parameters into each provider's own names and validates them before you spend a token. Vendor-specific knobs pass through with a namespace.

If anyone asks about secrets: the URI can carry them in the userinfo position, and a good implementation prefers an indirection like an env reference. One sentence, then move on.
