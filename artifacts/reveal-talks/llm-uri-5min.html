The proposal

Treat an LLM connection like a database connection.

llm://api.openai.com/gpt-5.2?reasoning_effort=none&temp=0.7&max_tokens=1500

llm://Scheme. The resource type. This is a model, not a database.
api.openai.comHost. The provider or API endpoint. Cloud, proxy, or localhost.
/gpt-5.2Path. The model, or a deployment of one.
?temp=0.7Query. Runtime configuration. Temperature, tokens, effort.

The exact syntax is not sacred. The abstraction is the point.

llm:// (5 min) | slide 2 | 90 seconds

Here is the entire idea. Put the provider, the model, and the runtime configuration into one portable URI. Walk left to right across the colored segments: scheme, host, path, query.

Today that same information lives in three places: the environment, the SDK constructor, and the call site. It is one logical dependency smeared across three layers.

Say the bottom line out loud. Nobody needs to defend the ampersand. What matters is that LLM configuration gets a connection-string abstraction at all.

Why it pays off immediately

Swapping models should be boring.

Zero application changes

export LLM_URL='llm://api.openai.com/gpt-5.2?temp=0'
my-agent

export LLM_URL='llm://api.anthropic.com/claude-sonnet'
my-agent

export LLM_URL='ollama://localhost:11434/qwen'
my-agent
PortableLaptop, CI, Docker, serverless, another language.
ParseableEvery language already ships a URL parser.
SerializableStore, pass, compare, override, redact.
Standard envelopePostgres and Redis differ too. The string still works.

We don't need AI-specific YAML for something URLs have handled for thirty years.

Demo moment. Same binary, three exports, three completely different backends, including a local model. The application consumes one conceptual input: here is the model connection.

Run the right column quickly. Portable, parseable, serializable. These come free because it is a URL.

Pre-empt the obvious objection with the last row. Every provider has different options. So do databases. Connection strings standardize the envelope, not every capability. Common parameters normalize; vendor-specific ones stay namespaced or pass through.

If anyone asks about secrets: the URI can carry them, and a good implementation should prefer an indirection such as credential=env:OPENAI_API_KEY. Keep that answer to one sentence here.
