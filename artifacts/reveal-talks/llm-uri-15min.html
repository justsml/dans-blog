So steal the database connection string

One logical dependency deserves one address.

environment · constructor · call site

// init  (keys and URLs come from .env)
new OpenAI({
  apiKey:  process.env.OPENAI_API_KEY,
  baseURL: process.env.OPENAI_BASE_URL,
})

// every call site
model: "gpt-5.2", temperature: 0.7,
maxTokens: 1500,
reasoning: { effort: "none" }

one string

LLM_URL=llm://api.openai.com/gpt-5.2
        ?reasoning_effort=none
        &temp=0.7
        &max_tokens=1500

// init, anywhere, any language
const model = connect(process.env.LLM_URL)

URLs already know how to do this

Three places it stops being aesthetic.

1 · CLI swap

my-agent

my-agent

Zero application changes.

2 · Eval matrix

# models.txt
llm://provider-a/model-a
llm://provider-b/model-b
llm://localhost/model-c

The runner iterates strings. Benchmarks and tests get the same loop.

3 · Router config

fast:      llm://provider/small
reasoning: llm://provider/frontier
local:     llm://localhost/qwen

A router is a map of names to connection strings.

Portable · parseableLaptop, CI, Docker, serverless, Kubernetes. Every language ships a URL parser.
Serializable · composableStore, pass, compare, override, validate, redact. Reuse config tooling you already have.

The objections, in the order you will hear them

Secrets. Provider differences. Failover.

“Credentials in a URL?”

llm://user:secret@provider/model

llm://provider/model?credential=env:OPENAI_API_KEY

URI syntax allows it. Logs, shell history, and telemetry say don't. Standardize the string; keep credential policy separate. Prefer indirection over literals.

“Every provider is different.”

llm://provider/model?temperature=.7&vendor.some_feature=true

So are Postgres, MySQL, Redis, and Mongo. Connection strings standardize the envelope, not every capability. Common params normalize; vendor params get a namespace.

“What about fallback?”

llms://primary.example,backup.example/model

llm://provider/model?timeout=20s&retries=2

Databases eventually encoded SSL, timeouts, replicas, pools. Same problem class. Whether this exact syntax survives matters less than the abstraction.

The URI is an interchange format, not a claim that every model is the same.

llm:// (15 min) | slide 4 | 3.5 minutes

Card one is deliberately controversial. Yes, the syntax supports credentials. No, that does not license pasting secrets into dashboards. Separate the two ideas: connection-string standardization is useful; credential handling still matters. A production implementation might reference the credential by an env indirection or a secret manager.

Click, card two. Yes, providers differ. So do databases, and connection strings stayed useful because they standardize the envelope. Common parameters normalize; provider-specific ones stay namespaced or pass through.

Click, card three. The article proposes llms:// as the plural form for multi-host behavior. Databases went through the same evolution with replicas and failover.
