<blockquote class="inset">
**अपडेट:** यह लेख [`llm://` URI योजना के लिए एक Internet-Draft](https://datatracker.ietf.org/doc/draft-levy-llm-uri-scheme/) और एक सहायक [`llm-strings` npm पैकेज](https://www.npmjs.com/package/llm-strings) की ओर ले गया। कार्यान्वयन [GitHub पर](https://github.com/justsml/llm-strings) भी उपलब्ध है।
</blockquote>

वे बुरे पुराने दिन याद हैं जब डेटाबेस से जुड़ने का मतलब एनवायरनमेंट वेरिएबल्स की एक बिखरी हुई टोकरी संभालना होता था?

यह नाज़ुक कॉन्फ़िग का एक मीनार था। `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`... या रुको, क्या वह `DB_USERNAME` था? क्या यह `DB_PASS` है या `DB_PWD`? क्या इस बार `PG_*` प्रीफ़िक्स चाहिए? और टाइमआउट सेटिंग आखिर कहाँ जाती है?

यह ताश का एक कमज़ोर महल था, जो `HOST` को कैपिटलाइज़ करना भूल जाने पर आपके प्रोडक्शन बिल्ड को गिराने के लिए तैयार रहता था।

फिर, किसी के पास शानदार विचार आया कि बस एक URL¹ का उपयोग करें:

```bash
postgres://user:pass@host:5432/dbname
```

एक स्ट्रिंग। आपको जो कुछ चाहिए। सार्वभौमिक रूप से पार्सेबल। पोर्टेबल। क्या मैं कह सकता हूँ... सुंदर?

तो हम LLM के साथ ऐसा व्यवहार क्यों कर रहे हैं जैसे 1999 हो?

## Env Var विस्फोट

अभी, मेरी `.env` फ़ाइल परित्यक्त API कुंजियों का एक कब्रिस्तान जैसी दिखती है। `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `MISTRAL_API_KEY`, `GROQ_API_KEY`। और Azure के बारे में मुझे मत बताइए—सिर्फ "नमस्ते" कहने के लिए आपको एक एंडपॉइंट, एक डिप्लॉयमेंट नाम, एक API वर्शन और एक कुंजी चाहिए।

यह सिर्फ बदसूरत नहीं है; यह घर्षण है। हर बार जब मैं कोई मॉडल बदलना चाहता हूँ या कोई नया प्रदाता आज़माना चाहता हूँ, मैं इनिशियलाइज़ेशन कोड फिर से लिख रहा हूँ, विशेष पैरामीटर नामों के लिए डॉक्यूमेंटेशन खोज रहा हूँ, और अपने एनवायरनमेंट कॉन्फ़िग में तीन और लाइनें जोड़ रहा हूँ।

क्या होगा अगर हम बस... ~~चुरा लें~~ DB URL विचार उधार लें?

## LLM कनेक्शन स्ट्रिंग्स का परिचय

कल्पना करें कि आप अपने पूरे मॉडल इंटरफ़ेस को एक ही लाइन से कॉन्फ़िगर कर रहे हैं:

```bash
llm://api.openai.com/gpt-5.2?reasoning_effort=none&temp=0.7&max_tokens=1500
llm://api.z.ai/glm-4.7?top_p=0.9&cache=true
```

### LLM कनेक्शन स्ट्रिंग की संरचना

![LLM कनेक्शन स्ट्रिंग के भाग](../inline-url-diagram-dark.svg)

स्कीम `llm://` है। होस्ट प्रदाता का API बेस URL है। पथ मॉडल का नाम है। और क्वेरी पैरामीटर सभी रनटाइम विकल्पों को संभालते हैं जो आमतौर पर आपके कोड को अव्यवस्थित करते हैं।

## प्रमाणीकरण चाहिए? बढयिया, जोड़ दें।

बिलकुल `postgres://` की तरह, हम परमाणीकरण क सीधे इसमें बेक कर सकत हैं:

```bash
llm://app-name:sk-proj-123456@api.openai.com/gpt-5.2?reasoning_effort=none&temp=0.7
```

*नोट: हाँ, URLs में क्रेडेंशियल डालना सुरक्षा जोखम ह सकत है यदि आप उनहें सार्वजनिक लॉग में चिपकाते हैं। लेकिन आधुनिक लॉगिंग सेवाएँ इन पैटर्न को साफ करने में काफी अच्छी हैं, और ईमानदारी स, क्या आप अपनी `.env` फ़ाइल के साथ बहुत बेहतर व्यवहार कर रहे हैं? सत्यापित करें, स्वच्छ करें, और सावधानी से उपयोग करें।*

## लचीलापन? क्यों नहीं।

कई डेटाबेस लाइब्रेरीज़ मल्टीपल होस्ट निर्दिष्ट करके राउंड-रॉबिन फेलओवर का समर्थन करती हैं। हमारे AI एजेंटों को वही विश्वसनीयता क्यों नहीं मिलनी चाहिए?

```bash
llms://primary.gpt,backup.gpt/gpt-6?temp=0.9
```

`llms://` में वह `s` टाइपो नहीं है। यह बहुवचन है। यदि `primary.gpt` हैंग करता है, तो क्लाइंट स्वचालतः `backup.gpt` पर पुनःप्रयास करता है। किसी जटिल राउटर तर्क की आवश्यकता नहीं।

<blockquote class="inset">एक स्टरिंग जिसमें सब कुछ है: आपका **प्रमाणीकरण** से लेकर **एंडपॉइंट** तक **हाइपरपैरामीटर** तक।</blockquote>

## विकल्पी फॉरमैट

मैं `llm://` से बंधा नहीं हूँ। विशिष्ट स्कीम मानक से कम महत्वपूर्ण है।

मैं एक ऐसी दुनिया की कल्पना कर सकता हूँ जहाँ हम संक्षिप्तता के लिए प्रदाता-विशिष्ट स्कीम का उपयोग करते हैं, जबकि मानक संरचना बनाए रखते हैं:

```bash
ollama://localhost:11434/llama3
vercel://anthropic/sonnet-4.5?temp=0.8&web_search={"maxUses":3}
bedrock://us-west-2.aws/anthropic/sonnet-4.5?temp=0.8&cacheControl=ephemeral
```

सटीक सिंटैक्स की परवाह किए बिना, मुख्य लाभ निर्विवाद हैं:

1.  **पोर्टेबिलिटी:** अपने पूरे कॉन्फ़िग को एक स्थानीय स्क्रिप्ट से क्लाउड वर्कर में कॉपी और पेस्ट करें।
2.  **CLI-अनुकूल:** अपनी स्क्रिप्ट्स में एक एकल आर्गुमेंट पास करें। `my-agent --model "llm://..."` `my-agent --model gpt-4 --temp 0.7 --key $KEY --host ...` से बेहतर है।
3.  **भाषा-अज्ञेय:** हर प्रोग्रामिंग भाषा में एक मजबूत URL पार्सर होता है। हमें मान्यकरण, पार्सिंग, और स्वच्छीकरण मुफ्त में मिलता है।

<blockquote class="ai-responce insett">डेटाबेस की दुनिया ने इसे समझने में दशकों लिए।<br /><b>अच्छी खबर, AI टाइमलाइन्स में, यह लगभग आध वाइब-वर्ष पहले की बात है।</b></blockquote>

## निष्कर्ष

हमें किसी और जटिल कॉन्फ़िगरेशन मानक य नई YAML-आधारित मैनिफेस्ट फ़ाइल की आवश्यकता नहीं ह। हमें बस उस एक उपकरण का उपयोग करने की आवश्यकता है जो पिछले 30 वर्षों से इंटरनेट के बाकी हिस्सों के लिए काम कर रहा है।

चलिए पहिया का पुनराविष्कार करना बंद करें और अपने LLM कनेक्शंस को वही सम्मान देना शुरू करें जो हम अपने डेटाबेस को देतें। आपकी `.env` फ़ाइल (और आपकी मानसिकता) आपको धन्यवाद देगी।
