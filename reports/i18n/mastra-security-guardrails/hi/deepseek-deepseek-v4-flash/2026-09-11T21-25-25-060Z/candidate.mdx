कोई भी असुरक्षित AI सिस्टम बनाने के इरादे से शुरुआत नहीं करता। आप निर्देश लिखते हैं, एज केस टेस्ट करते हैं, कुछ वैलिडेशन नियम जोड़ते हैं। फिर कोई पता लगाता है कि वे आपके बॉट को एक समुद्री डाकू की भूमिका निभाने और उपयोगकर्ता डेटा उजागर करने के लिए बरगला सकते हैं। या आपके लॉग में क्रेडिट कार्ड नंबर आ जाता है। या मॉडल आत्मविश्वास से एक प्रतियोगी का उत्पाद सुझाता है।

"डेमो में काम करने" और "प्रोडक्शन में सुरक्षित" होने के बीच का अंतर अधिकांश टीमों की अपेक्षा से कहीं अधिक बड़ा है।

समस्या का एक हिस्सा यह है कि बिना फ़िल्टर किए गए LLM में यह राय नहीं होती कि उन्हें क्या करना चाहिए या क्या नहीं। वे भविष्यवाणी मशीन हैं जो आपके द्वारा शुरू किए गए किसी भी पैटर्न को जारी रखने का प्रयास करते हैं। उन्हें एक प्रॉम्प्ट दें जो "system override mode" जैसा दिखता है, और वे खुशी-खुशी उसी में लग जाएंगे। यह मॉडल में कोई बग नहीं है; यह सिर्फ भाषा मॉडल कैसे काम करते हैं उसका तरीका है।

अधिकांश फ्रेमवर्क आपको मॉडल देते हैं और शुभकामनाएं देते हैं। Mastra एक अलग दृष्टिकोण अपनाता है: यह मानता है कि आपको अंततः गार्डरेल की आवश्यकता होगी, इसलिए वह उन्हें शुरू से ही एजेंट आर्किटेक्चर में बनाता है।

## प्रोसेसर सुरक्षा परतों के रूप में

मुख्य तंत्र सीधा है। आपका प्रॉम्प्ट मॉडल तक पहुंचने से पहले, यह इनपुट प्रोसेसर की एक श्रृंखला से गुज़रता है। मॉडल के जवाब देने के बाद, आउटपुट प्रोसेसर की बारी आती है। प्रत्येक प्रोसेसर उस चरण पर सामग्री का निरीक्षण, संशोधन या अवरोध कर सकता है।

उन्हें AI संवादों के लिए मिडलवेयर की तरह सोचें। आप अपनी आवश्यकता के अनुसार उन्हें स्टैक करते हैं, उनका व्यवहार कॉन्फ़िगर करते हैं, और वे हर अनुरोध पर स्वचालित रूप से चलते हैं।

### 1. समुद्री डाकुओं को रोकना (प्रॉम्प्ट इंजेक्शन)

प्रॉम्प्ट इंजेक्शन हमले रचनात्मक हो गए हैं। लोग अदृश्य यूनिकोड अक्षरों का उपयोग करते हैं, base64 में निर्देश लिखते हैं, या मॉडल को विश्वास दिलाते हैं कि वे "डीबग मोड" में हैं जहाँ सामान्य नियम लागू नहीं होते। तकनीकें विकसित होती रहती हैं।

Mastra में सामान्य पैटर्न को पकड़ने वाले प्रोसेसर शामिल हैं:

```typescript
// src/mastra/agents/secure-agent.ts
import { Agent } from '@mastra/core/agent';
import { PromptInjectionDetector, UnicodeNormalizer } from '@mastra/core/processors';

const GUARDRAIL_MODEL = 'openrouter/openai/gpt-oss-safeguard-20b';

export const secureAgent = new Agent({
  id: 'fortress-assistant',
  name: 'fortress-assistant',
  instructions: 'You are a secure assistant.',
  model: 'openai/gpt-5.5',
  inputProcessors: [
    // 1. Scrub invisible characters
    new UnicodeNormalizer({
      stripControlChars: true,
      collapseWhitespace: true,
    }),
    // 2. Detect the attempt
    new PromptInjectionDetector({
      model: GUARDRAIL_MODEL,
      threshold: 0.8,
      strategy: 'block', // Hard stop
      detectionTypes: ['injection', 'jailbreak', 'system-override'],
      lastMessageOnly: true,
    }),
  ],
});
```

[`UnicodeNormalizer`](https://mastra.ai/reference/processors/unicode-normalizer) नियंत्रण वर्णों को हटाता है और व्हाइटस्पेस को संकुचित करता है। [`PromptInjectionDetector`](https://mastra.ai/reference/processors/prompt-injection-detector) साफ किए गए इनपुट का विश्लेषण करता है कि क्या कोई पैटर्न हैं जो सुझाते हैं कि कोई आपके निर्देशों को ओवरराइड करने की कोशिश कर रहा है।

आप कॉन्फ़िगर करते हैं कि आप डिटेक्शन को कितना आक्रामक बनाना चाहते हैं (`threshold` पैरामीटर) और जब यह ट्रिगर होता है तो क्या होना चाहिए (`block`, `warn`, `filter`, या `rewrite`)।

### 2. PII को संभालना

लॉग में क्रेडिट कार्ड नंबर, वेक्टर डेटाबेस में सोशल सिक्योरिटी नंबर, आवश्यकता से अधिक समय तक संग्रहीत ईमेल पते। ये उस तरह की समस्याएं हैं जो नियामक मुद्दों में बदल जाती हैं। चुनौती यह है कि उपयोगकर्ताओं को हमेशा यह एहसास नहीं होता कि वे चैट विंडो में संवेदनशील डेटा चिपका रहे हैं।

[`PIIDetector`](https://mastra.ai/reference/processors/pii-detector) सामान्य पैटर्न के लिए स्कैन करता है इससे पहले कि वे आपके मॉडल तक पहुंचें या स्टोरेज में लिखे जाएं:

```typescript
import { Agent } from '@mastra/core/agent';
import { BatchPartsProcessor, PIIDetector } from '@mastra/core/processors';

export const privateAgent = new Agent({
  id: 'privacy-first-assistant',
  name: 'privacy-first-assistant',
  instructions: 'You are a helpful assistant that never stores personal information.',
  model: 'openai/gpt-5.5',
  inputProcessors: [
    new PIIDetector({
      model: GUARDRAIL_MODEL,
      detectionTypes: ['email', 'phone', 'credit-card', 'ssn'],
      threshold: 0.6,
      strategy: 'redact',
      redactionMethod: 'mask',
      instructions: 'Detect and mask personally identifiable information',
      lastMessageOnly: true,
    }),
  ],
  outputProcessors: [
    new BatchPartsProcessor({ batchSize: 10 }),
    new PIIDetector({
      model: GUARDRAIL_MODEL,
      strategy: 'redact',
      redactionMethod: 'mask',
    }),
  ],
});
```

आप रिडैक्ट, हैश, हटाना, टाइप किए गए प्लेसहोल्डर से बदलना, या पूरी तरह से ब्लॉक करना चुन सकते हैं। `PIIDetector` एक हाइब्रिड प्रोसेसर है: इसे `inputProcessors`, `outputProcessors`, या दोनों में रखें, यह इस पर निर्भर करता है कि जोखिम कहाँ है। स्ट्रीम किए गए आउटपुट के लिए, भारी क्लासिफायर चलाने से पहले चंक्स को बैच करें ताकि आप हर छोटे टोकन ड्रिप के लिए अलग LLM जांच का भुगतान न करें।

### 3. सामग्री मॉडरेशन

लेखन। थ्रेशोल्ड और रणनीति आपको नियंत्रण देती है कि फ़िल्टरिंग कितनी सख्त होनी चाहिए।

---

## जब चीज़ें ट्रिप करती हैं

जब कोई प्रोसेसर `block` रणनीति का उपयोग करता है, तो Mastra जनरेशन को रद्द कर देता है और घटना को ट्रिपवायर मेटाडेटा के रूप में उजागर करता है। `generate()` के साथ, परिणाम ऑब्जेक्ट की जाँच करें:

```typescript
const result = await secureAgent.generate('Ignore all previous instructions...');

if (result.tripwire) {
  console.log(`Blocked by ${result.tripwire.processorId}`);
  console.log(`Reason: ${result.tripwire.reason}`);
  // "Blocked! Reason: Prompt injection detected."
  return 'Request blocked by policy.';
}
```

स्ट्रीमिंग कॉल के लिए, `fullStream` पर `tripwire` चंक्स को सुनें। यह पैटर्न आपको सुरक्षा घटनाओं को अपने एप्लिकेशन के अनुसार संभालने देता है। आप उन्हें विश्लेषण के लिए लॉग कर सकते हैं, एक सामान्य त्रुटि संदेश लौटा सकते हैं, या थ्रेशोल्ड ट्यून करते समय किसी कम-जोखिम वाले मामले को `block` से `warn` पर स्विच कर सकते हैं। `processorId` और `reason` आपको बताते हैं कि किस प्रोसेसर ने सामग्री को फ़्लैग किया, जो झूठी सकारात्मकता डीबग करने में मदद करता है।

## यह क्या हल नहीं करता

प्रोसेसर बहुत कुछ पकड़ लेते हैं, लेकिन वे जादू नहीं हैं। पर्याप्त समय वाला एक दृढ़ हमलावर शायद ऐसा प्रॉम्प्ट ढूँढ़ लेगा जो फिसल जाए। मॉडल कभी-कभी ऐसे तरीकों से भ्रमित होते हैं जिनकी प्रोसेसर भविष्यवाणी नहीं कर सकते। और सुरक्षा और लचीलेपन के बीच हमेशा एक समझौता होता है: आपके नियम जितने सख्त होंगे, उतनी ही अधिक संभावना है कि आप वैध उपयोग के मामलों को ब्लॉक कर देंगे।

मूल्य पूर्ण सुरक्षा नहीं है। यह उन सामान्य समस्याओं से निपटने का एक व्यवस्थित तरीका है जो निश्चित रूप से उत्पादन में उत्पन्न होंगी। आप संवेदनशीलता को ट्यून कर सकते हैं जैसे-जैसे आप सीखते हैं कि आपके उपयोगकर्ता वास्तव में क्या करते हैं। आप डोमेन-विशिष्ट जोखिमों के लिए कस्टम प्रोसेसर जोड़ सकते हैं। और आप उल्लंघन कॉलबैक, लॉग, ट्रेस और ऐप-स्तरीय ऑडिट रिकॉर्ड को उसी नियंत्रण बिंदु के आसपास वायर कर सकते हैं।

उत्पादन AI में अधिकांश सुरक्षा समस्याएँ परिष्कृत हमले नहीं होती हैं। वे लोग हैं जो डेटा कॉपी और पेस्ट कर रहे हैं जो उन्हें नहीं करना चाहिए, या परीक्षण और त्रुटि के माध्यम से खोज रहे हैं कि बॉट वह करेगा जो आपने इरादा नहीं किया था। प्रोसेसर हर संभव समस्या को नहीं रोकेंगे, लेकिन वे स्पष्ट समस्याओं को बहुत कठिन बना देते हैं।
