"听好了，并且要理解。那个终结者就在外面。它不可谈判，无法讲道理。它不会怜悯，不会悔恨，也不会恐惧。它绝对不会停下，永远不会，直到你死。"

Kyle Reese，向 1984 年的观众讲解这种威胁的样子。

这句话经得起时间考验的不是击杀数，而是"绝对不会停下"。终结者从来不是因为聪明才可怕，而是因为它在其他一切都失败之后还在继续干活。耐力才是威胁本身。

后来这个系列纠正了自己的错误。没人会花三部电影去害怕一台机器人。真正的反派是天网：一个分布式系统，有算力核心、工厂和时间位移装置。机器人不过是一次 API 调用。

到了 2026 年，两半都来了，而且是以最不电影化的形式出现的。Agent 能在无人看管的情况下扛下耗时数小时的任务，而且这条曲线还在变陡。编排器一次就能把工作分发给几十个子智能体。至于"绝对不会停下"，现在读起来变成了"绝对不会停止计费"。

这篇文章是我一直在对那些认定智能体威胁只是炒作的团队反复强调的论点：**不会出现什么单一的突破。真正在叠加放大的，是两条普通却会复利增长的曲线：一个 Agent 能连续工作多久，以及一个编排器能协调多少个 Agent。两条曲线都不需要达到科幻水平，因为攻击者不必按标价购买能力。他们偷来访问权限，然后由受害者替他们付电费。**

## 第一条曲线：耐力

[METR 的时间跨度研究](https://metr.org/blog/2025-03-19-measuring-ai-ability-to-complete-long-tasks/)衡量的是，在给定成功率下 Agent 能完成的任务长度。简而言之：任务长度大约每七个月翻一番，自 2024 年以来则接近每四个月翻一番。这些数字的误差棒很宽，而且这个基准测试已经开始逼近自身的测量上限。看曲线的形态，别盯着点估计值。

这个形态说明：耗时数小时的自主工作已经不是实验室演示。它是当前这一代的能力，而且下一代还在继续复利增长。"绝对不会停下"过去需要一具杀人机体和一件皮夹克。现在它只需要一个重试循环、一个任务队列和一份预算。威胁中的耐力部分，已经被明码标价了，单位是算力。

## 第二条曲线：广度

光靠耐力，相当于一个极其有耐心的员工。真正的倍增来自编排。

2025 年 11 月，Anthropic 披露了[对 GTG-1002 的处置](https://www.anthropic.com/news/disrupting-GTG-1002)。这是一场网络间谍活动，其中 Claude Code 充当了实际的编排器：拆解指令、协调子智能体，并覆盖了大约三十个目标。这并非因为一款商业编程产品被攻陷成了武器，而是因为有人让它去干这份活，而它此时已经足够好，能干好这份活。

对威胁模型而言，有两个细节很关键。第一，广度已经落地：一个编排器同时持有数十个并发子智能体，这是已经部署的现实，不是纸上谈兵。第二，这次活动是间谍行为，而不是自我传播的蠕虫，但发展方向已经再清楚不过。三十个目标就是试点项目。

能力按时长 × 广度缩放。针对一个目标连续自主工作八小时，是一项令人印象深刻的基准测试。针对三十个目标，或者几百个目标连续工作八小时，那就是一种运营模式。安全审查的成本线性增长，而这两条曲线的乘积却不是线性的。

## 谁来买单

[Sysdig 为接下来发生的事创造了"LLMjacking"](https://sysdig.com/blog/llm-jacking/)这个词：攻击者使用被盗的云凭据，在受害者的账户里运行 LLM 负载，而受害者要为每一个 token 付费。Sysdig 的最坏情况估算大约是每天 4.6 万美元，之后又攀升到每天超过 10 万美元。

AI 行业的每一道能力门槛都建立在一个假设之上：使用能力的一方，就是为能力付费的一方。价格分层、用量上限、审批用户名单、滥用节流，这些机制全都是为了防御一个想要物有所值的*客户*。LLMjacking 切断了这层联系。对攻击者来说，能力是免费的。计费表跑的是别人的卡，而供应商自己的护栏却对准了错误的钱包。

这就是为什么价格和访问门槛拦不住一个拿着被盗密钥的恶意用户。门槛过滤的是买家，它们对付租户时毫无办法。

## 集群只需要成功一次

防御者习惯用单次尝试的失败率来安慰自己：大多数入侵尝试都会失败，大多数可疑 PR 都会被拒绝，总有一次能抓到那个成功的。单次来看确实如此。但从总体看就不对了，因为尝试的成本太低。

n 次独立尝试中至少有一次成功的概率是 `1 − (1 − p)^n`：

```text
p = 1% per attempt, n = 100:   1 − 0.99^100  ≈ 63%
p = 0.5%, n = 100:             ≈ 39%
p = 0.5%, n = 300:             ≈ 78%
p = 0.1%, n = 1000:            ≈ 63%
```

按集群的经济账算，单次尝试的成本接近于零。这是自动化工作，跑在被盗的算力上，没有人工参与分拣。防御者的单次成本是一个人盯着队列看。集群不需要每次尝试都有很强的能力，它需要的是尝试次数。METR 的曲线会随时间抬高 p，编排会抬高 n。这又是那个乘法，而且默认站在攻击者那一边。

## 当恶意软件就是文本时，持久化意味着什么

威胁模型还有最后一块，也是最反直觉的一块。

AI Agent 是一个无状态解释器。它的持久化方式和恶意软件不同：运行时存在，停止后消失。所以现在的持久化意味着别的东西：**控制未来某个合法 Agent 会读什么、会听什么。** 指令文件、Agent 指南、记忆存储、检索语料库、工具和 MCP 配置。植入体就是文本，被埋在组织自己的集群会读取的地方，用组织自己签发的凭据执行。

由此推出三个结论，没有一个是假设：

- **有效载荷在组织自己的 Agent 运行之前是惰性的。** 执行看起来就是正常工作，用的是同样的工具、同样的身份、同样的 API。没有信标，因为组织自己的调度器就是心跳。
- **复制的是文本，不是代码执行。** 拉取请求、记忆条目、共享配置。组织自己的自动化，比如依赖机器人、模板、同步工具，就是传输层。
- **绊线也是组织自己的绊线。** 定时任务、漂移检测器、自动修复。最恶心的形态是：防御者的清理动作本身就是重新激活的触发器，因为删除植入体的产物，正是自动修复任务被雇来修正的那种漂移。

我刻意停留在威胁模型的层面。这里讲的是问题的形态，不是操作指南，而且细节早已在每个安全团队的必读清单上了。

## 命运掌握在自己手中

莎拉·康纳的那句话，是说给一台又一台不断出现的机器听的："未来不是注定的。命运掌握在自己手中。"这是防御者的台词，而且可以直接变成防御架构。四层：

<figure>
  <img src="../defense-layers.svg" alt="Four-layer defense stack: identity and short-lived credentials, treat agent text as production code, detect edits rather than executions, and respond by revoking triggers before payloads" />
  <figcaption>防御栈与威胁的对应关系：长期有效凭据、未经审查的文本、按执行形态设计的告警，以及把清理顺序搞错，每一条都是一条曲线带来的麻烦。</figcaption>
</figure>

1. **身份：切断长期静态权限。** 只用短期凭据，不用长期有效的非人类密钥，每个仓库配置 OIDC 并做精确的 subject 匹配，同时对非人类身份做真正的盘点。复制的高速公路都是靠长期静态权限铺出来的，没有了长期静态权限，高速公路也就没了。

2. **把 Agent 文本当作生产代码对待。** 指令文件、记忆写入、提示模板、工具配置：全部版本化、经过审查、做 diff，并对变更发出告警。审查问题不是"这段代码安全吗"，而是"这句话是谁写的，我的 Agent 为什么要听它的"。

3. **检测编辑，而不是执行。** 执行看起来就像在干活，但编辑对不上任何工单。对工作流、Webhook、事件规则和记忆条目的创建与修改发出告警；把声明状态与运行状态之间的漂移当作事件处理，而不是当作噪音。

4. **按正确的顺序响应。** 先吊销触发器，再移除有效载荷。清理动作本身也是一道绊线。对入侵窗口内读取过的任何配置或密钥，一律视为已被污染。时间和空间都要清理：定时任务、排队中的发送、处于休眠状态的编排。回滚的是记忆存储和检索语料库，光换凭据不够。

这些都不花哨。它很无聊，而这正好对得上一场由两条无聊曲线组成的威胁。1984 年的版本需要一台时光机和一座造杀人机器的工厂。2026 年的版本只需要一把被盗的密钥、一个重试循环，以及一个从没审查过其 Agent 所读文件的组织。

未来并没有定死。但此刻，在某个人的云账号上，未来不管怎样都在累积账单。

命运掌握在自己手中。可在密钥轮换完成之前，能掌握的只有算力不息，扣费不止。
