“听着，听清楚了。那个终结者就在外面。你没法和它谈判，没法和它讲道理。它没有怜悯，没有悔恨，没有恐惧。它绝不会停下，绝不，直到你死去。”

1984 年，凯尔·里斯（Kyle Reese）向当时的人们这样描述威胁的本质。

随着时间推移，真正站得住脚的台词不是杀人数量，而是“绝不会停下”。终结者之所以可怕，从来不是因为它聪明，而是因为在其他手段全部失效后，它依然在持续运转。威胁的核心是耐力。

随后，这个系列电影修正了自己的逻辑盲区。没人会连着看三部电影只为了害怕同一个机器人。天网才是真正的反派：一个拥有核心、工厂和时间位移装备的分布式系统。而那个机器人，不过是一次 API 调用。

到了 2026 年，这两个拼图以最不具戏剧感的形式双双落地。智能体无需人类照看即可承担长达数小时的任务，且这项能力的增长曲线还在不断变陡；编排器将工作分发给几十个子智能体并发执行；而“绝不会停下”，如今直白地变成了“算力不息，扣费不止”。

这篇文章是我一直在向那些认为智能体威胁只是炒作的团队强调的论点：**不会有什么单一的技术质变。取而代之的，是两条普通却在不断复合增长的曲线相互交织——单个智能体能运行多久，以及单个编排器能协同多少个智能体。这两者都不需要达到科幻级别，因为攻击者根本不会按标价购买算力。他们盗取访问权限，让受害者替自己买单。**

## 曲线一：耐力

[METR 关于时间跨度的研究](https://metr.org/blog/2025-03-19-measuring-ai-ability-to-complete-long-tasks/)衡量了智能体在特定成功率下能够完成任务的时长。简而言之：任务时长大约每七个月翻一番——而自 2024 年以来，这个周期已经缩短至接近四个月。这些数据包含很大的误差棒，而且该基准测试本身就已经逼近其测量极限。重点看曲线的走势，而不是具体的一两个点估计值。

走势表明：长达数小时的自主运行并非实验室演示，而是当前这一代模型的现状，下一代还会继续复利增长。“绝不会停下”在过去需要一副杀人机甲和一件皮夹克；而现在，它只需要一个重试循环、一个任务队列和一笔预算。耐力这项威胁指标早已被明码标价——以算力的形式。

## 曲线二：广度

光有耐力，充其量只是一个极具耐心的员工。真正的倍增效应来自编排。

2025 年 11 月，Anthropic 披露了[挫败 GTG-1002 攻击行动](https://www.anthropic.com/news/disrupting-GTG-1002)的细节，这是一场网络间谍活动，其中 Claude Code 充当了作战编排器的角色：拆解指令、协调子智能体，并在大约三十个目标之间展开作业。一款商业化编程产品之所以能做到这一点，不是因为它被篡改成了武器，而是因为有人给它下达了任务，而它现在的能力恰好足以胜任。

对威胁模型而言，有两个细节至关重要。首先，广度已经具备：单个编排器掌控几十个并发子智能体已是实战现状，而非停留在论文层面。其次，这场行动是间谍窃密，而不是具备自我传播能力的蠕虫——但其演进方向已经昭然若揭。三十个目标不过是一次试运行。

AI 行业设立的每一个能力门槛，都建立在同一个假设之上：使用能力的一方就是为此付费的一方。价格档位、使用限额、白名单用户、滥用限流——所有这一切防范的都是一个追求性价比的*客户*。LLMjacking 彻底切断了这一关联。对攻击者而言，这种能力完全免费。跑表扣费扣在别人的信用卡上，而提供商自带的安全护栏全在对着错误的钱包使劲。

这就是为什么价格和访问门槛拦不住一个手握盗取密钥的恶意攻击者。

## 集群只需得手一次

防御者常常用单次尝试的失败率来安慰自己：绝大多数入侵尝试都会失败，绝大多数可疑 PR 都会被驳回，只要那次得逞的攻击出现，我们一定能抓得住。就单次尝试而言，这确实成立。但放在全局来看，是大错特错，因为攻击尝试的成本极其廉价。

在 n 次独立尝试中至少成功一次的概率是 `1 − (1 − p)^n`：

```text
p = 1% per attempt, n = 100:   1 − 0.99^100  ≈ 63%
p = 0.5%, n = 100:             ≈ 39%
p = 0.5%, n = 300:             ≈ 78%
p = 0.1%, n = 1000:            ≈ 63%
```

在集群经济学面前，单次尝试的成本几乎为零——自动化运行，跑在偷来的算力上，连人工分诊都不需要。而防御者应对单次尝试的成本，却是一个坐在那里人工过队列的真人。集群根本不需要每次尝试都具备极高能力；它只需要足够的尝试次数。METR 的曲线随着时间推移不断抬高 p。编排能力则不断推高 n。这又是乘积效应在起作用，且默认朝着有利于攻击者的方向持续复利。

## 当恶意软件变为文本，持久化意味着什么

威胁模型中还有最后一块拼图，也是最反直觉的一块。

AI 智能体是一个无状态解释器。它不会像传统恶意软件那样持久驻留——它在运行时存在，停下来时便烟消云散。因此，现在的持久化有了全新的定义：**控制未来的合法智能体将要读取并服从的内容。** 指令文件、智能体准则、记忆存储、检索语料库、工具以及 MCP 配置。此时的植入体就是文本，它被埋设在组织自有智能体机群读取数据的地方，并用组织自己签发的凭据完成执行。

随之而来的是三个既成事实的后果，无一属于凭空假设：

- **在组织自己的智能体运行它之前，有效载荷完全处于休眠状态。** 执行过程看起来与日常工作无异——相同的工具、相同的身份、相同的 API。这里没有外部信标，因为组织自己的调度器就是它的心跳。
- **复制意味着诱导文本被拷贝，而非促成代码被执行。** Pull request、记忆条目、共享配置。组织自己的自动化设施——依赖更新机器人、模板、同步工具——直接充当了传播的传输层。
- **绊线就是组织自己的绊线。** 定时任务、漂移检测器、自动修复。最阴险的场景莫过于：防御者执行的清理工作，反而成了重新激活攻击的触发器，因为删除植入体的残留产物，恰恰制造了自动修复任务被雇来纠正的运行漂移。

我特意将讨论保持在威胁模型的宏观高度——这是问题的形态，而非攻击教程，而且相关细节早已列在每个安全团队的必读清单上。

## 命运掌握在自己手中

莎拉·康纳留给那些不断降临的机器人的口信是：“未来尚未注定。命运掌握在自己手中。”这是防御者的底线准则，它可以直接转化为一套纵深防御架构。共分四层：

<figure>
  <img src="../defense-layers.svg" alt="四层防御架构：身份与短期凭据、将智能体文本视为生产代码、检测修改而非执行、按先撤销触发器后清理有效载荷的顺序响应" />
  <figcaption>针对威胁构建的防御架构：长期有效凭据、未经审查的文本、按执行特征报警以及颠倒清理顺序，每一个都足以引发指数级失控。</figcaption>
</figure>

1. **身份——断绝长期静态权限。** 仅使用短期凭据，杜绝长期有效的非人类密钥，实施精确匹配主体的单仓库 OIDC，并对非人类身份建立真实的资产清单。复制蔓延的高速公路全由长期静态权限铺就；没有长期静态权限，就没有公路可走。

2. **将智能体文本视为生产代码。** 指令文件、记忆写入、提示词模板、工具配置：全量纳入版本控制、实施审查、监控 diff，并对变更配置告警。审查时的核心问题不再是“这段代码安全吗”——而是“这句话是谁写的，为什么我的智能体必须服从它”。

3. **检测修改，而非执行。** 正常执行看起来完全就是在干活。但那些恶意修改根本对不上任何工单。盯紧工作流、Webhook、事件规则和记忆条目的创建与变更，并将声明状态与运行状态之间的漂移定性为安全事件，而不是日常噪音。

4. **按正确的顺序响应。** 移除有效载荷前，先撤销触发器——清理动作本身就是一条绊线。凡是在失陷窗口期内被读取过的配置或机密，一律视为已被污染。既要清理空间，也要清算时间：检查定时任务、队列中的待发消息、处于休眠状态的编排任务。除了轮换凭据，还要回滚记忆存储和检索语料库。

这套打法没有半点玄学。它枯燥至极，但也正适合用来对付两条同样枯燥演进的威胁曲线。1984 年的版本还需要时光机和生产杀戮机器的兵工厂。2026 年的版本，只需要一把偷来的密钥、一段重试循环，再加上一家从不审查智能体读取文件的倒霉公司。

未来尚未注定。但在此时此刻，无论结局如何，某个倒霉蛋的云账户上，跑表都在疯狂扣费。

命运掌握在自己手中——而且，在密钥完成轮换之前，算力不息，扣费不止。
