# Findings and chunking decision

The selected Qwen comparison is **Qwen 3.8 Flash and Qwen 3.8 27B**, per the user's clarification. Both request thinking disabled and 24,000 output tokens. All 216 selected-model/input pairs are completed once; unrelated Qwen calls made before the clarification remain supplemental. Four in-flight requests were interrupted and their charges are unknown.

- **Flash:** 8/8 synthetic controls, 10/10 full translations parsed; approximately $0.0029 per parsed real verdict and 23.14 seconds mean successful latency. One real result says ready while suggesting medium/high fixes. It correctly identified untranslated paragraphs and modified Pagefind executable paths in the Hindi serverless article.
- **27B:** 8/8 controls, 6/10 real translations parsed. Four long responses have malformed JSON despite finish reason `stop`, so these are not output-limit failures. Failure-inclusive cost is approximately $0.0327 per parsed real verdict, about 11 times Flash's. Increasing the cap alone does not repair invalid JSON.
- Minimum thinking is a cost/configuration preference, not a quality guarantee: both Luna models missed the stale-heading-anchor control at none (7/8 each), while the other selected models passed 8/8.
- GLM and DeepSeek still produced capped outputs at 24k; disabling optional DeepSeek thinking did not prevent excessive visible output. A separate DeepSeek result lost 81 malformed suggestion objects during normalization. Model-output contract checks deserve attention alongside chunk size.

## Should chunking change?

**Test model-specific judge chunking for Qwen 27B first, then DeepSeek and GLM.** The current evidence shows document-level reliability problems; it does not yet prove a chunking fix. Flash has no parse failure in this ten-case sample, so a smaller default for it is not justified by this run alone.

Use section boundaries for articles and complete Challenge/question units for quizzes; never split code fences, JSX elements, or answer/explanation groups. Align corresponding source and target units, retain the repository contract and surrounding context, and perform a final document-level omission/anchor/consistency pass. Fail the whole evaluation if any required chunk fails. Do not average away missing chunks or let a clean chunk override a serious defect elsewhere.

Measure the same failed and clean documents at full-document and section-based settings: valid complete JSON, exact suggestion matches, planted-defect coverage, false alarms, total cost and end-to-end latency including the final pass. Choose a token target from that experiment rather than inventing a universal 2k/4k cutoff. This turn preserves the full-document baseline; production chunking has not been changed.
